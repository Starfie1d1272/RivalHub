# PR #772 桌面工作流复审（第二版）

本目录是当前界面的复审证据。离线阅读请打开 `index.html`；每张截图均为 **1920×1080**，长页面按滚动位置分段。赛事、队伍、选手和设备均为本地隔离样例。

## 正常操作顺序

1. 在赛事比赛总览认领解说、选择本场。工作台显示首发状态和直接进入 BP 的入口。
2. 双方队长在已有 BP 页面确认准备、选择先后手，完成禁图、选图、选边。主区域显示本轮操作与倒计时，首发名单放在展开区域。
3. 回到工作台，按正式 BP 地图计划创建 Perfect 房间。只复制轮次、比赛短描述、队伍 1、队伍 2、GOTV 线路 2 延迟 120、Password 1 六项。
4. Mizar 正常时显示“Map 1 · Ancient 进行中”和自动记录状态；纯人工比赛直接提供比分录入。认领信息单独显示。
5. 正式地图结束后，从 completed_at 计算图间时长，10 分钟软提醒。准备下一图和补上一图基础板可以并行。下一图开打后结束图间提醒。
6. 完赛后分别核对正式结果、实际进行地图的数据、实际解说与录像。2:0 只检查两张地图；解说资料沿用认领和实际解说名单。

轮次来自阶段计划与轮次/赛制事实；比赛短描述复用赛事对阵格式化；地图和起始边来自正式 BP 结果。`missing` 专门演示真实资料缺失，其余示例都有完整赛事阶段、轮次和队伍。Perfect 的比赛归属指选择该赛事，设置项沿用 #610 指引。

## 异常及处理

| 情景 | 工作台展示 | 处理方式 |
| --- | --- | --- |
| 房间/地图错误 | 正式地图与收到的地图并排 | 检查 Perfect 房间与 Mizar 当前比赛/采集来源；有效新开始证据通过核验后恢复自动记录 |
| 首发有差异 | 待核对首发、额外或重复玩家，以 Steam 昵称及主页链接展示 | 检查采集对象；实际换人通过已有首发管理登记 |
| 比赛数据暂未更新 | 数据更新状态与采集检查指引 | 检查 Mizar 的游戏采集和连接；需要人工收尾时展开备用录分 |
| 当前地图绑定缺失 | 正式计划第一张待完成地图 | 明确确认恢复并接管本图，服务端复核 session、epoch、地图顺序并审计 |
| 已接管后切换采集来源 | generation 变化后的空绑定与冲突 | 相同受限恢复入口重新绑定，再提交人工赛果 |
| 正式比分需要更正 | 对应地图的更正入口 | 填新比分与原因，核对确认；服务器检查旧比分，防止覆盖他人修改 |
| DAK 待处理 | 对应地图 needs_attention 详情 | 按既有 Demo 复核入口处理，再次上传/核验 |
| 他人设备授权 | 授权人、关联比赛、操作权限 | 授权人处理；超级管理员填写原因并确认影响范围 |

手动录分确认说明当前地图范围及下一图恢复条件。采集、HUD 和设备来源继续由各自链路管理。刷新显示完成时间，读取最新处理状态。

## 实际操作验证

使用本地 Next.js、Chromium 和 PostgreSQL 17，真实管理员/队长 session：

- 两位队长完成整套 BP，核对数据库写入的三张地图与起始边；管理员恢复先手选择后再次走完 BP。修复恢复先手选择后倒计时为空、队长按钮一直禁用的问题。
- 空地图绑定：取消确认、再次确认、恢复后录分、刷新保持正式结果；正常无 Mizar 人工录分与刷新。
- 进行中地图比分更正，确认原因和新旧比分；六项复制逐项读取真实剪贴板。
- DAK 前 110 个可编辑数值字段（十人×十一项）；DAK 后 30 个平台字段；实际解说确认与刷新。
- 返回导航、更新反馈、同级管理员权限、超级管理员确认取消；8 种状态各在 320/390px 验证横向布局。
- 真实 PostgreSQL：Mizar ingest / 工作台 / 赛果语义共 33 项，LIVE capacity 18 项；覆盖同 epoch generation 切换空绑定恢复、错图、迟到/重复、显式接管、下一图恢复、gameplay 后 stale 接管和正常人工比赛。Steam 昵称优先及查询缺失回退也由实际数据库回归验证。
- 定向单元/组件测试、完整 app/tests/scripts 类型检查、变更文件 ESLint、architecture check、diff check。最终远端 required CI 见 PR 最新 HEAD。

截图内的外部上报来自协议样例，DAK 使用隔离证据包；浏览器内的 BP、确认和提交均实际执行。Perfect 建房、真实 CS2 采集和 OBS 推流仍需跨产品现场联调。

## 剩余范围

- Mizar 目前每个 epoch 只发送一次 map_started；本仓库已支持新的有效开始证据重新核验。相同 epoch 回到正确房间后能否自动产生新证据，仍取决于生产端。单独结束事件保持安全拒绝。
- identity 协议目前只提供总体状态与 reason。阵容差异已在本仓库补齐；完整双方队伍逐项差异仍需生产端提供事实。
- 进行中更正若使系列赛提前结束，当前服务端明确拒绝；该类系列赛恢复仍需专门处置流程。已完成地图的一般比分更正已接通。
- 公开 Radar/直播 viewer、Mizar OBS/场景控制、DAK pipeline 及 #610/#613/#764 其余专项分别验收。

共享 `presentation-phase.ts` 保持单一实现。admin 私有证据 DTO 增加 Steam 昵称/主页 projection；逐图更正通过 `map-score-correction.ts` 接收预期旧比分和原因。已发布赛事政策保持原样。
