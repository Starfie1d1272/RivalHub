# 覆盖核对与证据边界

核对对象是 `main@4ca5f800c44ea2611f82e18fcbede2077e3cdafc` 的**产品文档覆盖**，不是对全部代码的安全审计，也不是生产验收报告。产品正文、源码证据和当前入口清单分开存放；本轮增加资料包及文档入口，并修正核对发现的三处维护文档表述，不改产品行为或已发布规则。

## 核对方法

1. 拉取启动时远端 main 并以 `ls-remote` 再核对 SHA；从该 commit 建分支，保持整个资料包同一证据时间截面，不在调查途中悄悄切换新基线。
2. 先读取 AGENTS、CONTRIBUTING、文档 authority、领域/流程/权限/隐私资料和现行已发布规则，再检查代码；README、路线图和历史说明不直接作为“已实现且已上线”的证据。
3. 从所有当前页面和 HTTP 路由反查产品面；从 actions、领域服务、schema 与 active migrations 再反向核对无页面的能力、权限、状态和业务约束，避免仅按页面列表写产品。
4. 对关键流程查看已有测试场景与断言，例如名单变更仍保持长期队伍、资格赛结果恢复的下游限制、短通知排期、LIVE 范围、测试赛隔离。测试源码引用与本轮执行测试明确区分。
5. 按“谁 → 何时 → 前提 → 操作 → 成立的事实 → 拒绝/恢复 → 后续影响”检查主流程；按“政策要求/业务契约/实现选择/未知”检查措辞。
6. 对产品事实 E01–E24 和入口清单中的源码链接核验基线文件及行号；核对内部文档链接、编号引用、完整 diff、未跟踪文件及文档外变更。
