# #784 隔离实验覆盖表

本表仅归纳已执行证据，不定义运行时预算。所有容量实验均使用本地共享 PostgreSQL 17.11 的独立 scratch database；具体数据集、精确测量 SHA、逐请求耗时、有效 timeout、错误、停止点与复现命令见各报告。每轮遇失败或池队列达到预设阈值停止继续升载；队列和锁等待为采样值，可能漏峰。以下梯度的 1/2/4/8 均各三轮，16 均在首轮达到队列止损后停止，不是 16 档三轮通过。

| 原计划范围 | 证据与可证明结论 | 边界 |
| --- | --- | --- |
| 多赛事 Demo 确认与身份撤销 | [不同与共享身份梯度](demo-identity.md)各 74 项确认/撤销事务观察到提交；共享身份额外验证跨赛事撤销和等待中的重校验。 | 每档为确认数另加一次撤销；并发重确认可能在撤销后合法重建别名，不能宣称永久撤销。 |
| 同/不同账户预测或 BET | [BET 同账户及两账户](README.md)、[预测草稿及完整提交](prediction-drafts.md)各有隔离梯度，核对归属、余额及已知请求的幂等。 | “不同账户”只有两账户，仍共享赛事 program 锁；不是独立用户容量上限。 |
| 真实截止与提交交错 | [预测墙钟回归](prediction-drafts.md)以 PG `clock_timestamp()` 检查完整预测在截止前等待、截止后拒绝；BET 有实际行锁边界回归。 | 墙钟跨截止是一项受控交错，不是全梯度；不涉及 HTTP。 |
| 结算与提交交错 | [结算与已知回执重试梯度](settlement.md)分别让结算 owner 和已提交下注重试 owner 先持锁；各 61 个并发任务成功，结算批次和账本不重复，余额守恒。 | 两条入口都先执行 reconciliation，不能称回执返回先于结算；已确认回执可重试，未知写入不重放。已完赛盘口的新下注按业务规则不可接受。 |
| 更正与提交交错 | [更正持锁梯度](prediction-drafts.md)观察迟到下注等待、余额反转及幂等。 | 比赛在更正前已完赛，拒绝不能归因于更正；比分直接测试更新，未覆盖正式更正入口。 |
| 慢 SQL、持锁、池排队 | [更正持锁实验](prediction-drafts.md)在实际业务事务中持有锁并执行 200ms `pg_sleep`；[BET 故障回归](README.md)核验池获取、行锁和 statement timeout 及释放后恢复。 | 模拟 sleep 不等于真实慢查询；故障矩阵没有覆盖所有业务事务或网络未知提交。 |
| HTTP、provider、多人扇出、多实例及出站费用 | 不在本批隔离 PG 任务内；不将逻辑/HTTP 字节视为 provider egress。 | 不推断生产配额、吞吐、预算或费用。 |

这些结果不意味着 #784 全部完成：需由总控根据用途判断真实开赛/更正入口、墙钟截止梯度、长持锁故障、真实 provider 和目标规模是否需要额外证据。没有生产压测、部署、合并或 runtime budget 修改。
