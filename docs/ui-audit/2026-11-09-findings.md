## 共享基础设施

### UIA-009 · 单届载入短暂显示空白

**P2 · 性能与状态反馈 · A · R5。** 浏览者和参赛者在切换 `/[seasonSlug]/*` 时上一轮观察到短暂空白。赛事壳保留了最小高度，fallback 只有 `aria-busy` 与名称，详情尚无可见内容。见 `src/app/[seasonSlug]/layout.tsx:32,89`。

保留固定槽位，补轻量可见状态并复用可读的加载语义，单独测慢响应和小屏首屏。双主题从语义底色取值，布局保持可预期。命令 `$impeccable harden`。

### UIA-010 · 正文实际回退到系统字体

**P2 · 实现一致性 · A · R6。** 线上首页、数据中心、忘记密码的正文或标题计算样式为系统栈。SH-01 确认根 `--font-sans` 为空而 body 有 `--font-geist`。Tailwind 将根 alias 在 body 的变量可见之前求值，编译证据见 SH-04。源位 `src/app/layout.tsx:17,58`、`src/app/globals.css:102,156`。

在能解析 Geist 的层定义 alias，保留 Noto Sans SC 与 JetBrains Mono 的既有角色。验证计算样式、字体加载和标题换行，再同步 DESIGN.md。两种主题共用字体系，320px 下复核长标题和字段高度。命令 `$impeccable typeset`。

### UIA-012 · 页面存在嵌套主要地标

**P2 · 可访问性 · A／S · R1。** `/settings/competitive` 和后台样本均见 2 个 `main`，其中 1 个嵌套。根 layout 已提供主要地标，设置与后台 layout 又各提供一个。BP 和 DAK/Mizar 接入页也存在子 `main`，为源码证据。见 SH-03 与 `src/app/layout.tsx:69`、`src/app/settings/layout.tsx:10`、`src/app/admin/layout.tsx:25`、`src/app/[seasonSlug]/matches/[matchId]/veto/page.tsx:24`。[HTML main 契约](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element)

在共享壳指定唯一主要地标，局部改用 section/容器，结合标题和跳过导航复核键盘路径。语义在桌面、窄屏和主题间复用。命令 `$impeccable harden`。

### UIA-016 · 全站与通知没有统一的颜色模式状态

**P2 · 主题准备 · A／S · R3。** 根固定 `class="dark"` 和 `color-scheme: dark`，SH-01 在系统偏好非暗色的会话也如此。应用未挂 ThemeProvider，`ui/sonner.tsx:10` 的通知主题单独回退到 system。本轮没有制造业务通知来判断实际通知色。见 `src/app/layout.tsx:54,75`、`src/app/globals.css:151`。

先定义模式与色彩 token 的唯一 owner，再让 HTML、表单原生控件和通知消费同一 resolved mode。切换入口要同时验证窄屏、首帧、无脚本回退和恢复系统偏好。命令 `$impeccable shape`。

### UIA-017 · 赛事颜色覆盖与 Portal 跨了不同 CSS 作用域

**P2 · 主题 · A（赛事值）／C＋S（作用域） · R3／E09。** 历史 Rivals 赛事主色 `#f97316`，根为 `#ff6b1a`。本机 Chrome 用真实 Button、Input、Select 和编译 CSS 重现：赛事 wrapper 内直接取主色和 Button 焦点采用局部色，共享主按钮填色和 Select 焦点别名仍为根橙。Dialog、Select、DropdownMenu 与 HelpTooltip 出现在赛事 wrapper 外；浮层中直接使用赛事色也读到根橙。HelpTooltip 的普通背景仍按中性浮层角色展示。见 `src/app/[seasonSlug]/layout.tsx:50–58`、`globals.css:18–36` 与 [FZ-02](evidence/2026-11-09-technical.md#fz-02--主题作用域与实测配色)。

让品牌／赛事主色与焦点在各自 scope 求值；浮层按 owner 继承语义色。保留独立 UI 角色的颜色选择，验收两种模式、按钮、选中态、焦点和窄屏 Portal。命令 `$impeccable extract`（规划）或 `$impeccable harden`。

### UIA-019 · 非对阵树页面加载 legacy 样式

**P3 · 性能与隔离 · A · R5。** `/stats` DOM 已挂载 `/brackets-viewer.min.css`，根布局全局引入。文件本地 6,859 B，线上独立 HTTP 响应传输 1,654 B。消费位置为 `BracketView.tsx:401`。证据 SH-07 与 `src/app/layout.tsx:56`。

将 vendor 样式归到对阵树入口，查切换进入时样式是否及时加载。独立控制其暗色和浅色适配，保持原来的局部横滚。命令 `$impeccable optimize`。

### UIA-032 · 自定义赛事色的输入范围超过可读配色范围

**P2 · 主题与可访问性 · C＋S · R3／E09。** `src/lib/seasons/edit.ts:81` 接受任意六位 hex，`src/lib/utils/color.ts:18–25` 按固定阈值选文字并以输入作焦点色。隔离 Chrome 中 `#777777` 的实算文字为 `#0a0c10`，对比 **4.37:1**；白色也只有 **4.48:1**。`#111111` 用在 Button 直接读的焦点环上，对页面背景为 **1.04:1**、对普通面板 **1.02:1**。Select 仍取根别名，参见 UIA-017。这些是合法边界样本，未改变实际赛事配置。默认输入边界仍归 UIA-015。

保留自定义赛事主色的识别用途，按用途确定可读的填充／前景及独立焦点色；当前深色和浅色分别测正常文字、控件边界及焦点的实际相邻色。命令 `$impeccable colorize`。

### UIA-038 · 读取与失败态的页面几何不一致

**P2 · 实现一致性与响应式 · S · R1。** 赛事信息读取用 narrow、正常用 wide。Stats 正常和读取为 workbench、error 与 not-found 为 wide。社区奖读取只用局部 padding，成功用 wide。源位 `src/app/[seasonSlug]/info/page.tsx:11,29`、`src/app/stats/{page,error,not-found}.tsx`、`src/app/[seasonSlug]/community-awards/page.tsx:13,37`。没有以此推断实测 CLS。 选秀及队长选人也从 workbench 读取壳切到 standard 禁用／等待壳（`draft/page.tsx:18–45`、`draft/captain/page.tsx:26–32,149–158`）。

同一路由使用一致的 PageLayout 组合，再保留各自的骨架、错误和正文。320px 复核内外留白，桌面复核内容起点，双主题保持几何。命令 `$impeccable harden`。

## 公共组件

### UIA-004 · 必读文字复用了装饰灰

**P1 · 可访问性 · A · R3。** 赛务排期约束、已完赛时间、R2 Conversion 样本数基线约 2.68:1、2.82:1、2.75:1。本轮公共与后台评估扩展到统计结果数、排名门槛、当前分页、跨赛事审计 4 个 12px 筛选标签和后台横向滑动说明。见 `ScheduledAtInput.tsx:160`、`MatchHeroHeader.tsx:183`、`MetricValue.tsx:65`、`StatsDataTable.tsx:171,192`、`AuditLogTable.tsx:81,130,159,180`、`AdminSidebar.tsx:90`。[WCAG 2.2 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum) 末轮源码确认队长阵容的主次位置和后台阻塞原因也使用装饰灰，待对实际表面复算（`TeamDraftGrid.tsx:136`、`DraftAdminPanel.tsx:146–154`）。

按信息角色替换为现有可读次要/关键前景，装饰 token 继续承担装饰。核对两种主题和紧凑行实际前后景，统一表头、说明与元数据角色。命令 `$impeccable polish`。

### UIA-006 · 指标帮助过小，Escape 后仍显示

**P2 · 可访问性与触屏 · A · R2。** 数据中心的 R2 Conversion 指标说明 8×14 CSS px，Enter 打开，Escape 后仍在。浮层 `pointer-events:none`，离开触发器即关闭。角色涉及需要指标说明的选手、观众和办赛者。源位 `src/components/rivalhub/HelpTooltip.tsx:57–81`，见 SH-02。

保留一个共享 HelpTooltip，扩大热区并验证相邻目标间距，支持 Escape、点击开合及移入浮层阅读。44px 可作为触屏舒适目标，AA 尺寸需按 24px 与间距例外逐例判断。按主题取浮层色，在窄表内验收定位与焦点。命令 `$impeccable harden`。[WCAG 2.2 悬停或焦点内容](https://www.w3.org/TR/WCAG22/#content-on-hover-or-focus) · [目标大小](https://www.w3.org/TR/WCAG22/#target-size-minimum)

### UIA-013 · 可见字段名未成为可访问名称

**P1 · 可访问性 · A／S · R2。** `/settings/competitive` 已填资料样本的 12 个控件中 9 个未关联可见标签，涉及历史/近期段位、星数、Rating 和资料状态。后台比赛执行的 4 个 combobox 都缺少范围标签，两处「全部队伍」写同一 `team`，界面未说明同时筛选两个区域。UIA-002、005 记录各自流程症状。共享 `Field` 只在调用者传 id 时关联 Label 与 Input，多处赛事信息编辑调用没有 id，开放报名及队长邀请有同类源码证据。见 `CompetitiveProfileForm.tsx:242–333`、`AdminMatchFilter.tsx:43,63,95`、`Field.tsx:27–49`、`SeasonPublicInfoManager.tsx:117–118`、`RegistrationForm.tsx:356,430,459,493,573`、`TeamInvitationsSection.tsx:93`。

让字段包装拥有稳定 ID 和关联说明，在分组名中区分范围。Select、日期和搜索采用既有组件的命名入口，表单验证时给错误描述及焦点。主题共用标签，窄屏让标签与字段保持相邻。命令 `$impeccable harden`。[WCAG 2.2 名称、角色、值](https://www.w3.org/TR/WCAG22/#name-role-value)

### UIA-014 · 互斥选项的选择状态未暴露

**P1 · 可访问性 · A／S · R2。** 教育认证页按 Enter 切到「已毕业」后材料提示变化，两按钮仍无 `aria-pressed` 或 checked。登录方式和招募位置有同类自制选项，需根据各自语义复核。见 `src/components/settings/EducationVerificationPanel.tsx:301–315`、`src/components/auth/LoginForm.tsx:282–305`、`src/components/recruitment/RecruitmentLobbyControls.tsx:127`。 选秀位置筛选复用同类颜色选中模式；队长「我的阵容」也未暴露展开关系，桌面始终显示内容却改变 chevron（`PlayerPool.tsx:61–85`、`CaptainDraftPanel.tsx:202–219,307–337`，S）。

互斥选择采用有名称的单选语义，独立过滤按钮暴露 pressed，状态变化后能读到新要求。浅色和深色都用状态与文字表达选择，移动端保证点击区。命令 `$impeccable harden`。

### UIA-015 · 空输入难以从面板识别

**P1 · 可访问性 · A · R3。** 教育认证的空输入使用 `#1f2530` 边线、`#0d1016` 填充与 `#10131a` 面板，边线对相邻颜色约 1.21–1.24:1，填充对面板约 1.02:1。当前边界承担控件定位。源位 `src/components/ui/input.tsx`、`src/app/globals.css:35,39–52`，SH-05。

为依赖边界识别的控件单独定语义边框，与装饰分隔分开。分别查 Input、Textarea、Select 与 Checkbox 的静止、聚焦、错误和禁用状态。两种模式各校验，在小屏低亮度下优先。命令 `$impeccable colorize`。[WCAG 2.2 非文本对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)

### UIA-018 · 填色前景与背景分开硬编码

**P2 · 主题与可访问性 · C＋S · R3／E02、E09。** 隔离 Chrome 在真实直播组件的合成进行中场次测得白字对默认橙 **2.85:1**，共享 destructive Button 的默认浅字对危险色 **2.62:1**。同组件未选项引用未定义的 `--color-panel-lo`，背景计算为透明。MatchMapProfile、TeamMapProfile 使用固定黑字，在较深赛事色上存在同类风险（S）。源位 `MatchLiveViewing.tsx:75–85`、`MatchMapProfile.tsx:48`、`TeamMapProfile.tsx:39`、`src/components/ui/button.tsx:12–15`；[配色样本](evidence/2026-11-09-technical.md#fz-02--主题作用域与实测配色)。

### UIA-020 · 内联确认出现与关闭后焦点回到页面

**P2 · 键盘与实现一致性 · A／S · R2。** `/my/teams` 用 Enter 展开「退出队伍？」再取消，两次焦点都到 BODY，操作未执行。调用者条件切换触发按钮，`InlineConfirm` 不拥有初始焦点和恢复约定。更新提示、取消解说等有同模式待复核。见 `src/components/my/LeaveTeamControl.tsx:27–42`、`src/components/rivalhub/InlineConfirm.tsx`、`src/components/layout/DeploymentUpdateNotice.tsx:16`。

### UIA-024 · 自制 Tabs 不响应方向键

**P2 · 键盘与实现一致性 · A · R2。** 在组队大厅和 Stats Player/Team 指标视图实测 ArrowRight 无效，Tab 可以逐项抵达。自制 `role=tablist`／`role=tab` 没有面板关联或 roving tabindex。见 `src/components/recruitment/RecruitmentLobbyControls.tsx:88–109`、`src/components/stats/MetricFamilyTabs.tsx:22–49`。

### UIA-031 · 记录的字号和形状范围覆盖不全

**P3 · 设计系统一致性 · S · R6。** DESIGN.md 的 machine-readable ramp 仅收录 11px 标签，现有 UI contract 允许 10–11px 的等宽元数据。89 条命中中 50 条为 10px，5 条圆角建议含 PhaseStep 的 fallback。地图编号、PICK 和主比分属明确视觉角色。「草稿已恢复」为任务状态，既用 10px 又用无效的 `var(--color-ok)22` 颜色拼接。见 `docs/ui-system.md:69`、`RegistrationForm.tsx:325–326`、[检测明细](evidence/2026-11-09-detector.tsv)。

先区分紧凑元数据、必读说明、控件标签和系列大比分，再同步快照并回查实际漂移。共享字号和形状角色服务双主题与响应式，避免仅为检测改像素。命令 `$impeccable document`。

### UIA-039 · 中文对话框关闭控件使用英文名称

### UIA-040 · 拒绝重试的平滑滚动没有读取减弱动效偏好

**P3 · 动效 · S · R2。** 全局 CSS 在 reduced-motion 下缩短动画和过渡。教育核验驳回重试用 JS 显式 `scrollIntoView({ behavior: "smooth" })` 后立即聚焦。未启用系统偏好或制造驳回态实测。见 `globals.css:181–189`、`EducationVerificationPanel.tsx:150–153`。

### UIA-005 · Swiss 赛程的定位与重复焦点

**P2 · 响应式与键盘 · A · R1／R2。** 320px 抽查第 4 轮进行时从第 1 轮开始；30 场含 90 个同类详情链接，两个比分和一个箭头重复。队伍筛选的可见标签未绑定控件。见[基线复现](2026-11-09-baseline.md)与 `OfficialSwissFlow.tsx:146–161`、`MatchTeamFilter.tsx:41–45`。
