# RivalHub · 设计系统提取、浅色与分批计划

保留「赛事控制台」方向和「主色／对阵色／背景色」命名。公共比赛、参赛任务和办赛工作台共享一套颜色、字号、空间与交互语义。各自保留赛况、资料和操作密度。

## 现有系统与 Extract 范围

`src/app/globals.css` 拥有运行时色、字、圆角、动效和层级。Tailwind/shadcn 名称在这里映射到语义 token。`src/components/ui/` 拥有按钮、字段、Tabs、浮层、表格等基础控件，`src/components/rivalhub/` 拥有 PageLayout、页头、Panel、状态、列表和任务提示。业务目录拥有数据、权限和动作。`docs/ui-system.md` 记录交互约定，Impeccable 的 DESIGN.md 和 sidecar 提供提取快照。

按 Extract 的发现、识别和规划三步取证。用同意图的至少三个实例判断新抽象是否值得建立。现有组件可以修正后直接复用。共享实现优先从三处可核对消费者试迁移，再扩大到同类调用。

## 浅色模式现状与实施建议

运行时当前只有固定深色。已具备背景、面板、浮层、前景、警示、对阵和操作 token。SH-01 观测到浏览器系统偏好非暗色时页面仍是暗色。Sonner 从现有 next-themes 读取 theme，但应用壳未挂 provider。赛事自定义主色是在页面内部设置的，与根兼容 alias 和挂 body 的 Portal 有不同继承路径。[共享证据](evidence/2026-11-09-technical.md) · [UIA-016、017、032](2026-11-09-findings.md)

1. **确定模式和语义 owner。** 建议第一版保留深色默认，设置中提供深色、浅色、跟随系统。复用现有主题依赖时，让 HTML、`color-scheme`、toast、Radix 和原生表单读同一 resolved mode。首帧使用与偏好一致的主题，核对缓存、hydration、客户端切换、刷新与无脚本显示。公共根壳保持可缓存，若需要服务端持久偏好，应先评估缓存影响。
2. **先在深色中收敛 token 再加浅色映射。** 按页面／普通面板／内嵌面板／浮层、正文／次要／必读／装饰、分隔／控件边界／焦点、填充／前景定义角色。保留主色、对阵色、背景色的名称。示例中默认橙对白约 2.85:1，说明主色作文字与作填充需要不同的配色对。正常文字和控件依据对应的 WCAG 阈值按场景测量。[WCAG 2.2 对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) · [非文本对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)
3. **让赛事颜色覆盖实际消费者。** 根模式选择背景与前景，赛事 scope 再覆盖主色家族。别名在有局部值的层解析，Portal 取调用方需要的作用域。用默认色、Rivals 自定义色和合法但对比不足的边界样本检验按钮、文本、边界、选中态和焦点。参考实测与计算证据，不把未配置的颜色当作线上复现。
4. **处理组件专用表面与资产。** bracket vendor 样式、胜方行、live overlay、状态点、图表线、弹窗遮罩和纪念币卡片分别核对。直播视频背景、比赛地图、队徽和币面按媒体语义保留，浅色改外围 surface 和信息层级。表格、Radix Select、日期/文件控件、disabled/invalid/focus 要用实际浏览器复核。
5. **按状态矩阵验收后再扩大入口。** 桌面、768、390、320px 复核公开/已登录/管理代表路径、空/读取/失败/危险确认、真实对阵色、浮层开合与键盘焦点。双主题截图与 token 对照先基线后变更。用实际字号验算对比和长文本，另查缩放、减弱动效与触屏。最后将稳定约定写回 UI 系统并同步 Impeccable 提取快照。

## 视觉一致性方向

| 区域 | 可用性或一致性事实 | 后续审美选择 |
| --- | --- | --- |
| 首页、赛事与比赛 | 首页以本届和近期对阵为视觉中心。完赛依系列、地图、半场展开。单届读取空白、详情 H1 缺失及手机当前轮难找是可验证问题。 | 保留赛事标题、橙色主操作与等宽元数据。首屏在标题后突出一个可行动状态，周边卡片弱化边框装饰。直播、完赛、未开赛继续使用相同比赛身份。 |
| 数据、历史和队伍 | 真实统计有六个范围视图。局部宽表、固定身份列和排序语义有价值。搜索状态、当前范围及部分必要数字偏弱。 | 提高范围、样本和结果层级差，减少同等强调的边框与标签。数值列保留密度和等宽对齐，说明可展开，核心事实常驻。 |
| 账号与参赛 | 个人待办优先，锁定与确认分开呈现。教育 CTA 同排使 320px 说明窄至约 80px，存在状态提示重复和不同页壳。 | 单任务保持窄而清晰的阅读宽度；字段标签按任务文本，战术字型留给编号。锁定时让本人状态与本届帮助成为主层，材料细节可读后再操作。 |
| 赛务与后台 | 六阶段和执行／赛程／资料适配工作顺序，当前事项、前提和高影响操作的层级仍分散。 | 主工作区像赛事操作台，先出现当前对阵和可做动作，再出现核对表、资料和日志。保留语义强调线，危险操作用一致确认层。 |
| 共用质感 | 颜色、形状与字体有根契约，局部面板、字段边界和几何存在漂移。 | 用明度、边框和有限的层次阴影建立深度。普通页维持安静，赛事 Hero 和币面可承担更强材质。视觉检查关注节奏和优先级，不以统一卡片形状为目标。 |

表中右列为审美方向，左列的客观问题与系统偏差以[统一台账](2026-11-09-findings.md)为准。品牌视觉在深色与浅色中共用赛事标识、主色角色、对阵色和数据密度。

## 分批 PR 方案

按可以独立审查和回滚的边界交付。P1 防错和表单缺口可以先开，视觉方案在主题与页面状态契约稳定后推进。

| 批次与依赖 | 范围 | 最低验收与命令 |
| --- | --- | --- |
| 1A · 字段与选择 | 字段 label、组名、可见状态及输入边界，UIA-013、014、015、025。可独立推进。 | 竞技、教育、公开赛程与比赛执行的 AX 命名，空控件实际相邻色，键盘选择与错误关联。`harden`／`colorize`。 |

| 1C · 关键可读性 | UIA-004、018 的文字和填充前景。与主题 owner 协调，先交付当前深色配对。 | 实际背景验算普通文本和控件状态，覆盖赛务、Stats、审计、危险按钮和自定义赛事色样本。`colorize`。 |
