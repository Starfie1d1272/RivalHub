## 浅色模式现状与实施建议

运行时当前只有固定深色。已具备背景、面板、浮层、前景、警示、对阵和操作 token。SH-01 观测到浏览器系统偏好非暗色时页面仍是暗色。Sonner 从现有 next-themes 读取 theme，但应用壳未挂 provider。赛事主色设在页面内，根别名与 body Portal 各自从根读取；[FZ-02](evidence/2026-11-09-technical.md#fz-02--主题作用域与实测配色) 的真实组件样本确认了差异。[共享证据](evidence/2026-11-09-technical.md) · [UIA-016、017、032](2026-11-09-findings.md)

1. **确定模式和语义 owner。** 建议第一版保留深色默认，设置中提供深色、浅色、跟随系统。复用现有主题依赖时，让 HTML、`color-scheme`、toast、Radix 和原生表单读同一 resolved mode。首帧使用与偏好一致的主题，核对缓存、hydration、客户端切换、刷新与无脚本显示。公共根壳保持可缓存，若需要服务端持久偏好，应先评估缓存影响。
2. **先在深色中收敛 token 再加浅色映射。** 按页面／普通面板／内嵌面板／浮层、正文／次要／必读／装饰、分隔／控件边界／焦点、填充／前景定义角色。保留主色、对阵色、背景色的名称。示例中默认橙对白约 2.85:1，说明主色作文字与作填充需要不同的配色对。正常文字和控件依据对应的 WCAG 阈值按场景测量。[WCAG 2.2 对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) · [非文本对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)
3. **让赛事颜色覆盖实际消费者。** 根模式选择背景与前景，赛事 scope 再覆盖主色家族。别名在有局部值的层解析，Portal 取调用方需要的作用域。用默认色、Rivals 自定义色和合法但对比不足的边界样本检验按钮、文本、边界、选中态和焦点。用真实控件测量。需要调整主色用于可读文字的配色时，保留可辨识的赛事标识；单一输入色不同时承担静态边界、焦点和所有前景角色。
4. **处理组件专用表面与资产。** bracket vendor 样式、胜方行、live overlay、状态点、图表线、弹窗遮罩和纪念币卡片分别核对。直播视频背景、比赛地图、队徽和币面按媒体语义保留，浅色改外围 surface 和信息层级。表格、Radix Select、日期/文件控件、disabled/invalid/focus 要用实际浏览器复核。
5. **按状态矩阵验收后再扩大入口。** 桌面、768、390、320px 复核公开/已登录/管理代表路径、空/读取/失败/危险确认、真实对阵色、浮层开合与键盘焦点。双主题截图与 token 对照先基线后变更。用实际字号验算对比和长文本，另查缩放、减弱动效与触屏。最后将稳定约定写回 UI 系统并同步 Impeccable 提取快照。

### 末轮视觉对照

- **客观可用性。** 开放报名应区分草稿恢复、字段失败与回执；选秀后台应区分轮次阻塞和结束。320px 找回页仍把密码框置于解释和恢复路径之前，队长及办赛任务也要把原因、时限和可做动作放在同一视线范围。设计验收以实际任务和状态为单位。
- **设计系统漂移。** 1280px 历史票榜的 H1 为 30px，候选标题 20px；选秀回顾的 H1 同为 30px，阵容和选秀记录是 14px 面板标题。两页在 320px 未撑开文档。14px 面板标签可以服务密集阵容，主要队长任务、可操作提示和名单阻塞原因应采用共享的可读层级。禁用和等待页沿用各自常态的页面宽度；Loading、Empty 与 Error 共用几何和阅读顺序，保留不同业务文案。
- **可选的审美提升。** 把大标题和标志性主色留给赛事身份与关键时刻；让票数、顺位、截止时间与比分在列表中形成明确的数字轴。桌面并排看对阵与资料，手机先读状态和下一步，详情按需展开。保持必要的信息密度和局部横滚，用背景、面板与边线的层级区分区域，减少相邻区块同等强调。暗浅两版共用品牌、排版和业务结构。
